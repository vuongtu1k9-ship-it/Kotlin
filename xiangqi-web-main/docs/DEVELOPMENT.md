# Development Guide (Xiangqi Web)

This repo contains a Xiangqi (Chinese Chess / Cờ tướng) web app.

## Requirements
- **Node.js**: 20.0.0+ (LTS recommended)
- **NPM**: 9.0.0+
- **Vite**: 5.0+

## Quick Start
```bash
# 1. Install dependencies
npm install

# 2. Start dev server (Vite)
npm run dev

# 3. (Optional) Run backend with PM2 for background stability
npm run server:start
```

## 🧪 Testing
- **Local E2E Test**: `npm run test:deployment` (mặc định cho localhost:3000)
- **Dev Server Test**: `npm run test:dev` (kiểm tra https://dev.cotuong.xyz)

## Core Workflow Rules (Mandatory)

1.  **Command-Line Driven**: Use CLI tools (`gh`, `git`, `ssh`) for all interactions with GitHub (Actions, Issues, etc.) instead of the web UI.
2.  **Local-First Development**: Always perform code edits, style changes, and fixes in your local workspace/branch first.
3.  **No Direct Server Edits**: Editing files directly on the production or development servers is strictly forbidden. This ensures the repository remains the single source of truth.
4.  **Tiered Deployment**: Standard changes must be pushed to `main` (Dev Server), tested, and then merged to `production` (Prod Server).

## Project Layout (Modernized)
```bash
src/
  components/    Atomic UI components (Board, Chat, Auth)
  pages/         Page-level views (GamesPage, PracticePage, Admin)
  hooks/         Custom React hooks (useSocket, useAuth)
  state/         Global store (puzzles, game state)
  utils/         Xiangqi engine logic (moves, rules)
server/
  controllers/   Request handlers (Auth, GameControl)
  models/        MongoDB schemas (User, Game, Puzzle)
  services/      Business logic (ELO calculation, AI routing)
  scripts/       Migration and maintenance tools
```

## AI Integration

The game supports personality-driven dynamic AI bots managed via `/admin/bots`.

### Engine Stack
- **Web Engine**: Local browser-based AI (fallback / weak bots).
- **Pikafish**: Server-side UCI engine at `/opt/pikafish/pikafish` (Levels 1–6).

### Bot System
Bots are stored in MongoDB and fetched by frontend via `GET /api/bots/active`.  
Each bot has a `personality` (`aggressive` / `defensive` / `balanced`) and `level` (1–6).

The personality engine in `server/socket/engineHandlers.mjs` maps each bot to:
- **movetimeMs** — controls effective strength (short = weak, long = strong)
- **MultiPV** — number of candidate moves generated by Pikafish
- **VarietyScoreThreshold** — wrapper-level randomization within candidates
- **Move Overhead** — time management feel

See [`docs/AI_BOTS.md`](./AI_BOTS.md) for full specification.

### Seed Bots to DB

```bash
node --env-file=.env server/scripts/seedBots.mjs
```


## 🎨 UI/UX Design Standards

For a unified, premium experience across the platform, follow these layout and typography rules:

### 1. The Unified Layout
Every top-level page component must be wrapped in the `<Layout>` component (from `src/components/Layout.tsx`). 

**Structure Example:**
```tsx
import { Layout } from '../components/Layout';
import { SEO } from '../components/SEO';

export function NewPage() {
  return (
    <div className="mx-auto max-w-[1920px] w-full px-4 pt-8 pb-16 space-y-10">
      <SEO title="Page Title" description="..." />
      <div className="flex flex-col md:flex-row md:items-end justify-between gap-6">
        <div>
          <h1 className="text-4xl md:text-5xl font-black text-slate-900 dark:text-white tracking-tighter uppercase">
            PAGE TITLE
          </h1>
          <p className="text-sm font-medium text-slate-500 dark:text-white/50 mt-1">Subtitle description info.</p>
        </div>
      </div>
      <div className="main-content">
        {/* Page content here */}
      </div>
    </div>
  );
}
```

### 2. Typography Baseline (Accessibility)
- **Minimum Font Size**: Never use hardcoded sizes smaller than 12px (e.g., `text-[10px]`).
- **Standard Metadata/Small Text**: Use the `text-xs` (12px) or `text-sm` (14px) Tailwind tokens. 
- **Headings**: Page titles should be `text-4xl` or `text-5xl` with `font-black` and `tracking-tighter`.

### 3. Desktop Spacing
- Use `space-y-10` for vertical separation between major page sections.
- Use `p-8 md:p-12` for main content cards to provide a luxurious breathing room.
- Max container width should cap at `max-w-[1920px]`.
- **Glassmorphism**: Use `bg-white/80` or `dark:bg-white/[0.03]` with `backdrop-blur-md` for a premium look.


## 🔐 Security Hardening (Mandatory)

To prevent NoSQL Injection, ReDoS, and malicious state manipulation, follow these rules:

1. **Input Sanitization**: Always use `server/utils/security.mjs` utilities for MongoDB queries:
    - Use `safeString(val)` or `safeNumber(val)` for any user-provided query parameters.
    - Use `escapeRegex(val)` if you are performing a `$regex` search.
2. **Socket Validation**: Never trust incoming socket payloads.
    - Validate move coordinates (0-9, 0-8).
    - Verify the player's side matches the room state before applying server-side updates.
3. **Internal Routes**: Do not expose sensitive room IDs or player UIDs in public API responses unless necessary.

## 🪵 Logging & Error Handling (Mandatory)

To ensure system observability and faster debugging, **never leave a catch block empty or "silent"**. We follow a strict tagged logging convention.

1. **Tagged Logging Standard**: Every log must start with a `[TAG]` in brackets and UPPERCASE.
   - **DB & Cache**: `[MONGO]`, `[REDIS]`, `[SYS_CLEANUP]`
   - **Auth & Social**: `[AUTH]`, `[SOCKET]`, `[CHAT]`, `[INVITE]`, `[MESSAGES]`, `[PUSH]`
   - **Game & Automation**: `[GAME_STATE]`, `[ENGINE]`, `[BOT_MGR]`, `[GAME_SWEEPER]`, `[TOURNAMENT_SVC]`, `[SCORING]`
2. **No Silent Catches**: Every `try/catch` or `.catch()` must include a logging statement. Even if ignorable, log it at `debug` level with its tag.
3. **Standard Logger**:
   - **Server-side**: `import { logger } from '../logger.mjs'`.
   - **Client-side**: `import { logger } from '../utils/logger'`.
4. **Contextual Info**: Include a descriptive string, relevant IDs, and the error object:
   ```javascript
   try {
     await saveRoom(roomId, state);
   } catch (e) {
     logger.error(`[GAME_STATE] Failed to save room ${roomId}:`, e.message);
   }
   ```
5. **Monitoring Automated Systems**:
   Use `tail -f` and `grep` to monitor heartbeats and background tasks in real-time on Linux:
   - **Bots**: `tail -f server.log | grep "\[BOT_MGR\]"`
   - **Cleanups**: `tail -f server.log | grep -E "\[SYS_CLEANUP\]|\[GAME_SWEEPER\]"`
   - **AI SEO**: `tail -f server.log | grep "\[AI_GEN\]"`
   - **Errors**: `tail -f server.log | grep "ERROR"`


## 👥 Multi-User Local Testing (Tricks)
Để kiểm tra tính năng nhiều người chơi cùng lúc trên một máy tính mà không bị xung đột session (Cookie/LocalStorage):

1.  **Sử dụng nhiều Hostname khác nhau**: 
    Trình duyệt coi mỗi hostname sau là một "site" riêng biệt, giúp bạn đăng nhập 3 tài khoản khác nhau trên 3 tab:
    *   `http://localhost:3000` (Người chơi 1)
    *   `http://127.0.0.1:3000` (Người chơi 2)
    *   `http://0.0.0.0:3000` (Người chơi 3 - nếu hệ điều hành hỗ trợ)
    *   Hoặc sử dụng chế độ **Ẩn danh (Incognito)**.

2.  **Chạy Backend qua PM2**:
    Thay vì chạy `node server/index.mjs` trực tiếp, hãy dùng `npm run server:start`. Việc này giúp backend chạy ngầm ổn định, không bị tắt khi bạn restart Vite hoặc đóng terminal.
    *   Xem log: `pm2 logs xiangqi-server`
    *   Restart: `pm2 restart xiangqi-server`

## Troubleshooting
- If the board looks misaligned: hard refresh (cache).
- If you see TypeScript errors: ensure `npm install` finished successfully.
- Redis issues: Check `pm2 logs` and ensure Redis is running if rate limiting fails.
- Nếu port 3000 bị treo (Hold vĩnh viễn): Chạy `fuser -k 3000/tcp` để giải phóng port.
